# WSL用イメージ構築(AmazonLinux2023)
## 何、これ？
AmazonLinux2023をちょこちょことセットアップしてWSLにインポートするためのイメージを構築するのものです。WSL界隈ではサクッとインストールできるオンラインイメージでUbuntu、Archなどをお使いになる方が多いかもしれないですが、
仕事上AWSでAmazonLinux2023を相手することが多いので作っていますが、
「WSLでAL2023を普段遣いしたい！」みたいな需要もあるかなーと思って公開してみます。
私の詐欺用環境のためなので、以下のものが仕込まれています。
 - GoogleCloud CLIを利用できる
   - Google Cloud触る機会がないわけではないので、一応。
 - pyenv越しにPython3.1xを利用できる
   - AL2023にはPython3.9が同梱されていますが、これをPython3.10以降にアップグレードする公式な方法がないため
   - AL2023公式でPython3.10以降のRPMが配布されてはいますけど、｀cloud-initとかの都合でalternative等でサ切り替えるのを非推奨しょうとしてるのでダルいのです。
   - dnfを壊すかも、というビビリからバージョン指定をいじるところまではしてません。
 - Node.JSをAL2023公式より新しいものにする
   - LambdaのNode18サポート打ち切るってのに公式提供が１８のままなのは微妙よな、と思いまして。
   - 作り始めた頃は公式提供がなかったのでNodeSourceから入れるようにしてます。
   - パッケージ管理をpnpmベースに移行してあります。
 - HomeBrew(LinuxBrew)を利用できる
   - 特にパッケージの追加まではしてませんが、あると便利なので。
 - 主要AIエージェント
   業務で使うので、主要なものは入れられるようにしています。
   - Cursor Agent
   - Gemini CLI
   - Codex
   - Claude Code
 - カレントディレクトリがgitリポジトリだった場合、プロンプトに**ブランチ名**と**未コミットの資材があるか**を表示する
   - 私自身はインフラ屋ですが、TerraformやAnsibleでIaCな感じの作業するときに地味に便利です。 
 ```bash
 # 未コミット資材がある場合
 [USER@HOSTNAME current_dir][branch-name*]$ 
 # [ブランチ名*]のようにアスタリスクがつきます。

 # 未コミット資材がない（いわゆるクリーンな状態の）場合
 [USER@HOSTNAME current_dir][branch-name]$ 
 # [ブランチ名*]のようにアスタリスクがつきません。
 ```
 - SSHキーを配置します。
   - 作りながら思いましたが、共有ボリューム使う方法のが管理が楽な面があると思います。
     っていうか私はそうしています。

## 使用方法
### 環境設定ファイルの準備
```bash
$ cp .env.example .env
```
基本的にはログインユーザー名、グループ名を引き継ぐような仕込みとかをしていますが、
ご都合に応じてお好みのものに変更してください。


### SSHキーの配置
```bash
$ cp -rp ~/.ssh/* ./docker/ssh/
```

### イメージのビルド
```bash
$ make build
```

### コンテナの起動・ログイン
```bash
$ docker compose up -d
$ docker compose exec app bash
```

ダルいのでmake経由でできるようにしました。
```bash
## 無圧縮tarで出力(こっちが楽です)
$ make image
## xzで圧縮する場合
$ make image COMPRESS=xz
## gzipで圧縮する場合
$ make image COMPRESS=gzip
```
